# Telegram 用户会话

TG 用户会话用于 `listen_source=user_session` 的群和频道监听。二维码登录流程参考上游项目实现，会话保存在运行数据目录的 `.env` 中，不新增数据库表。

## 二维码登录

1. 从 `https://my.telegram.org/apps` 获取 `TG_API_ID` 和 `TG_API_HASH`。
2. 在“Bot / 面板设置”填写这两项；服务器需要代理时同时填写 `TG_PROXY`，然后先保存设置。
3. 点击“二维码登录”，使用 Telegram 手机端扫码并确认。
4. 面板显示“已配置，重启后连接”后重启 `tg-watchbot`。
5. 服务启动并连接成功后，状态显示“已连接”。

二维码约 60 秒后过期。重新生成二维码会关闭上一次未完成的登录连接。

## 登录状态与登出

- `未登录`：API 配置不完整，或没有 `TG_API_SESSION`。
- `已配置，重启后连接`：Session 已保存，但当前用户会话监听尚未连接。
- `已连接`：长期用户会话监听当前已连接 Telegram。

“登出会话”会断开当前用户会话连接、取消未完成的二维码登录，并清空 `.env` 中的 `TG_API_SESSION`。如需重新监听，扫码后重启服务。

## TG_PROXY

支持以下 URL 格式：

```text
socks5://127.0.0.1:1080
socks4://127.0.0.1:1080
http://127.0.0.1:7890
socks5://username:password@proxy.example.com:1080
```

不支持 `https://` 代理 URL，也不能包含路径、查询参数或片段。`TG_PROXY` 同时用于二维码登录和长期用户会话监听。

## 安全

`TG_API_HASH`、`TG_API_SESSION` 和带认证信息的 `TG_PROXY` 都属于敏感数据。运行数据目录中的 `.env` 会设为 `0600`，不要提交到 Git、粘贴到工单或写入公开日志。面板应继续通过本机回环监听配合可信反代访问。

面板主题按钮位于登录页右上角和主面板标题栏。主题偏好只保存在当前浏览器的 `localStorage`，不会写入服务器配置。
